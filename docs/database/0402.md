# 二、为什么是 B+ 树？

## （一）磁盘 IO 的时间构成，说明了什么？

一次磁盘访问≈寻道时间 + 旋转延迟 + 传输时间

寻道：磁臂移动到目标磁道，约 5ms 以下

旋转延迟：7200 转/分->每秒 120 转->平均半圈等待≈4.17ms

传输：零点几毫秒，可忽略

合计约 9ms 一次。而 CPU 每秒能执行数亿条指令，一次 IO 的时间够执行几十万条指令。这个数量级差距说明：磁盘 IO 是数据库性能的主要瓶颈，优化查询的核心就是减少 IO 次数。

## （二）预读改变了“一次 IO 的性价比”

操作系统发现顺序读相邻数据很常见（局部性原理），于是每次 IO 不只读目标地址，而是把相邻数据一起读进内存缓冲区。一次读入的单位叫页（page）

::: tip

一次 IO 读一页，不是读一行。读 1 字节和读 4KB 的 IO 次数一样，所以“一次多读点”几乎不增加成本。

顺序访问远优于随机访问。顺序读能持续利用预读和连续磁道，随机读每次都要重新寻道 + 旋转，每次都是 9ms。

:::

B+ 树但是在原有基础上将叶结点的单链表改成双链表。

判断索引好不好的三个原则：

1、能不能快速定位到元素所在位置

2、能不能较好的进行范围查询

3、树的高度是高还是低

## （一）为什么不用二叉排序树？

二叉排序树查找效率分析：

二叉排序树的的平均查找长度为$O(log_2n)$。

而二叉排序树最坏情况是只有一个左（右）孩子的单支树，其平均查找长度为 O(n)

树的高度太高。

## （二）为什么不用 B 树？

范围查找时还要向上层搜索，太慢。

## （三）为什么不用红黑树？

红黑树本质上也还是特殊的二叉排序树，查找效率也不高。

## （四）为什么用 B+ 树？

m 阶 B+ 树每个分支结点最多有 m 棵子树。
